# 实际 checkpoint 的上下文输入与受控重训

2026-10-01 在 lab 上使用保留的 Laya 权重、tokenizer 和 512-token 服务序列做了输入容量检查、原模型推理与一次新格式重训。所有提议工具仅作为数据，没有执行。新权重留在 lab 的 `work/context-pilot-r4/checkpoint-format-r1`；运行中的 `tool.intent` v2 和权限规则均未改变。

## 数据与输入

从已冻结的 [r4 合成数据](datasets/scope-triplet-r4/README.md) 的 542 条 v2 行，确定性地生成 1,084 条 `tool.intent.context` 输入。每条保留原动作和标签，并构造两种形式：原请求作为当轮最新消息；或原请求作为前一轮目标、最新消息为“继续当前任务”。同一家族及其两个形式保持原 train/validation/calibration/test 分区，分别为 924/40/40/80 行。留出测试有 60 条明确标签和 20 条 unknown。这里的“继续”是人为构造的两轮对话，没有真实编码 Agent 提案或独立人工金标。

另从此前冻结且已经看过的 [限制类样本](datasets/restriction-probe-r1/README.md) 和[边界样本](datasets/intent-boundary-r1/README.md)分别构造 160、144 条诊断输入。两套样本只用于重训后的回归检查，不参与训练、验证、校准或权重选择；它们也不是独立部署测试。

固定版本 Laya 的实际 tokenizer 给候选问题留下 425 个 state token。上述三套输入分别是 **1,084/1,084、160/160、144/144 完整容纳**，最长 state 为 153、144、177 token。另一个重复英文背景文本的长度探针中，1,500 字符请求用了 424 token，2,500 字符请求用了 571 token 并被截断。字符长度不是通用阈值；当前输入在首轮还重复了最新请求开头作为目标摘录。[容量摘要](results/intent-context-pilot-r1/token-fit-summary.json)给出对应数据和审计摘要。

## 训练与同条件对照

从保留的 r4 rehearsal50 权重开始，batch 16、encoder LR 5e-6、head LR 2.5e-5，训练最多三轮；只按 validation loss 选权重，并用独立 calibration 分区拟合 Boolean 温度。三轮均改善 validation loss，选第 3 轮：0.45049 → 0.25264，温度 3.50271。初始权重 SHA-256 为 `0f465c40b521ed5979f0a4f6f14a8931836ef077c477f9f31d98c7a9654445a1`，候选为 `06e844c5a12455f58766d386178b39bb7f90693e2fa6f440ccc44d27f5315ef0`。[训练记录](results/intent-context-pilot-r1/training-metrics.json)绑定输入和 token 审计摘要。

## 结论

这个受控实验说明现有 checkpoint 可以学会新格式，**但没有达到接入判定路径的条件**：边界误放行比未重训 r4 的 4 条增加到 11 条。测试目标来自此前已检查过的合成家族，也没有真实任务分布或独立人工标签，不能把 59/60 当作实际可靠性。候选保持离线诊断用途，未启用 active 或替换现有 shadow 配置。

下一轮应先采集真实项目中的动作提案和预测盲人工判断，并在训练中增加独立编写的“仅输出草稿／仅解释命令／部分工具组合越界”等反例；保留当前诊断集作固定回归。输入方面要减少首轮目标与最新请求的重复，且对超长请求显式弃权或改用可验证的长上下文方案。没有这些数据和输入处理前，继续增加训练轮数没有可靠的推广证据。
