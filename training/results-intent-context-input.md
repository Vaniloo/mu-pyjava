# `tool.intent` 候选输入：完整请求与任务约束

ScopeJudge 迁移实验发现大量领域不匹配和 512-token 截断；继续只调训练样本或参数，无法补回 judge 从未看到的任务信息。本阶段先固定输入契约，供后续真实项目采样与独立标注。没有新训练、人工金标或准确率结论。

## 已实现

- 在现有私有采样的 `source.intent_context` 中保存完整最新用户消息、SHA-256 和当轮 `TaskFrame`。已有 v2 `decision.state` 仍是最新请求前 1000 字符、工具名和动作参数；实际 judge 路由、阈值与权限不变。
- `prepare_intent_context.py` 从有效 v2 原始样本生成 `tool.intent.context` 审核包。候选 state 使用工具与动作参数、完整最新请求、带来源轮次的原文约束及任务目标摘录。目标只作背景。生成时校验消息摘要、任务状态结构和 v2 请求前缀的对应关系。
- 审核包不带预测、后端和权限结果；标签全为空。清单明确标记不能训练，未经 tokenizer 完整容纳检查不能推理。采样组的 `real_project` 身份仍需要显式说明，不能从路径自动推断。
- 候选 state 保存字段顺序和序列化摘要；token 审计按包中的候选问题计算容量，并核对 Laya 的实际序列化。超长输入要单独设计可验证的压缩或更大上下文，不能用静默裁剪的评测数代替完整输入评测。

## 验证与限制

测试通过真实 Agent 工具调用检查：旧 v2 state 不变，私有样本记录完整请求和末尾约束，新的审核包保留动作参数与约束但不含预测；审批拒绝时文件未写入。另测任务切换、证据篡改拒绝及候选问题/token 审计逻辑。完整 Python 回归为 257 项通过、1 项跳过。已核对固定依赖 `laya==0.3.20` 的 `serialize_state` 使用 `json.dumps(..., ensure_ascii=False)`，与候选包的有序 JSON 摘要一致。这些测试是构造场景，只验证数据路径，不是模型效果证据；本机没有训练依赖，尚未用实际 checkpoint 运行新包的 token fit。

当前 `TaskFrame.goal` 是最多 600 字符的目标摘录，可能已经过时；约束提取只覆盖显式 `Constraint:`/`约束:` 或状态判别出的修正。历史对话中的其他含义仍可能缺失。`write_file`/`edit_file` 继续仅提供路径和大小等元数据，不暴露文件正文；某些意图问题因此仍需弃权。现有 512-token 模型很可能容纳不了完整长请求，必须先测 token fit，再决定输入压缩和模型架构。真实编码 Agent 的动作提案及独立人工判断尚未采集到足以评估或重训；旧数据和本阶段测试不能冒充此类证据。

下一步是选择实际项目任务，按仓库或任务族采集工具提案；盲审候选输入并记录缺失上下文，同时量化 token fit。只有输入契约稳定、样本覆盖和独立 holdout 足够后，才讨论重训或上线。
